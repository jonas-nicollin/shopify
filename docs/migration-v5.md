# v0.5 migration: one Product grid

Canonical file: `sections/main-collection-product-grid.liquid`. It replaces the native section implementation and the former editorial implementation. The editor offers one **Product grid**, with optional editorial media. Native templates keep editorial media off by default; existing editorial templates retain their explicit setting. Shared Dawn card, image shapes, prices, quick add and facets markup remain available. The controller is now `<product-catalog>`.

Before replacing the section, back up all collection templates and affected host files. Audit references to both section types. Change each `main-collection-editorial-grid` instance to `main-collection-product-grid`, preserving its instance ID, order and merchant settings. Remove a redundant disabled native grid only if another migrated grid is present. The instance's editor name should be Product grid. After all references are migrated, remove the old file or leave a non-addable, inert migration marker in the draft. It is not shipped as a second implementation in this library.

`enable_pagination` is a new checkbox immediately above `products_per_page`: true renders Dawn's numbered pagination, false loads subsequent pages automatically. Default true selects numbered pages, as requested. Existing automatic integrations can explicitly set false. `products_per_page` retains its ID and accepts 8–72 in increments of 4. Plain links remain the no-JavaScript/failure fallback. The section overrides the legacy host rule hiding `.pagination__list` only in numbered mode. Ajaxinate is no longer used by the merged grid; the recovered asset remains archived for other legacy integrations.

Retired settings: `enable_lazy_load` (native cover-image loading is always used), `editorial_namespace`, `editorial_key`, `editorial_field` (fixed documented `custom.editorial_media` → `media` contract). Inspect these values before migration. If a shop uses different keys, migrate its data or adapt the documented connector before removing them; never silently switch an existing nonstandard mapping. The current integration used the documented keys. No product metafield data is changed.

Layout `page_width` retains its ID and numeric value but changes from a range to a number input. It accepts precise values such as 1920; Liquid uses a 1200 px fallback and 320 px minimum for blank/invalid small entries. `page_full_width` remains independent. Full-width Product grid follows Featured collection's native gutters: 15 px below 750 and from 990 px, 50 px between those breakpoints. No host Featured collection rewrite is needed.

Gallery `card_gallery_scrollbar` retains its ID and now has the label Show gallery indicator. `card_gallery_indicator_style` selects Bar (default) or Steps. Bar colors only the active segment on a transparent track. Steps shows centered short lines with inactive lines at 20% of the theme foreground. Both appear on hover/keyboard focus or temporary touch interaction. The current draft selects Steps for review.

Editorial dispatch adds a `collection` setting to each existing `dispatch_item` block. Empty image/title/link fields fall back to the selected collection's featured image/title/URL. Existing manual overrides stay intact. For old collection links, migrate the resource into `collection`, clear `link`, and clear only the old placeholder title `Title`; retain actual custom titles/images. New blocks have no placeholder title or invalid placeholder image preset. Shopify dynamic sources are useful for selected collection resources; the per-product media lookup inside Dawn's snippet loop still uses the code contract, not a single section-level dynamic source.

“Theme Settings” at the bottom of the editor's section panel is Shopify's automatically generated access to referenced global settings, not a second schema group maintained by this module. The section color scheme and global product-card color scheme have different scopes. Keep both. Custom schema labels use sentence case; platform-owned labels are not altered.
